# Wi-Fi 数值与语义显示协议

**主机状态机 LIMITED_PASS · ESP-IDF 传输、OLED 光学和时序 UNKNOWN**

R6 的 PREPARE/COMMIT 思想保留。V1 提议在局域网由一个经授权的协调器管理每个模块。节点发起持久 TCP/TLS 连接，双向身份认证，应用使用有限长度 JSON 帧（4 字节网络序长度，最大 2 KiB，UTF-8，拒绝重复字段、类型不符及未知版本）。Wi-Fi 链路保护之外仍核证发送者身份和成员白名单。组内节点编号、左右顺序和时钟版本均随会话冻结。新组先清空原组，收齐撤销回执或等待原 lease 排空后才能重新分组。局部独立模式允许协调器只向一板发事务，也允许板上本地受控数据源以同一状态机提供独立事务。组合模式不自动降级成独立有效读数。 [R6](../r6/COMMUNICATION_PROTOCOL.md)

## 统一数据模型

```json
{
  "module_id": "left",
  "group_id": "lab",
  "sequence": "42",
  "value": "123456789",
  "decimal_scale": 2,
  "label": "计数",
  "unit": "s",
  "source": "acquisition-1",
  "timestamp": 10000,
  "ttl": 3000,
  "status": "ok"
}
```

| 字段 | 约束 |
| --- | --- |
| module_id / group_id | 配置时设置，目标 ID 对应接收者。组配置持有固定有序成员，去重且长度为 1、2 或 3。 |
| sequence | 协调器在组会话内严格递增的 uint64，线格式用十进制字符串以保留精度。主机模型接收解析后的整数。相同序号且完全相同的有效事务可重回 ACK，冲突/旧帧拒绝。 |
| value / decimal_scale | 1–9 个 ASCII 数字的定点有效数字串，长度上限 3×成员数；整数形式按右对齐，保留输入前导零、剩余左侧补空。scale 从 0 到长度−1，至少显式留一整数位，例 123456789/2 表示 1234567.89。三块依序拿 123/456/789。筒上无小数点，OLED 的单位行加“末 2 位小数”或约定的等价短标记，各块同语义并显示组序号，例如 1/3。字段溢出、负值或文字截断造成含义不全时拒绝显示。 |
| label / unit / source | 分别最多 32/16/32 可打印字符，允许空单位。字形宽度作为独立校验，面板渲染无法完整表达时返回 NOT_READY。source 由协调器验证数据源白名单。 |
| timestamp / ttl | timestamp 为本协调会话参考单调时钟的采样毫秒，带 UTC 日志字段时另行保存。ttl 为 1–60000 ms，无源新样本不可刷新 timestamp。节点截止时间取 timestamp+ttl 扣除同步不确定度，并限制到展示租约。 |
| status | ok 帧才可能点亮。stale、invalid、offline、fault 是遥测/清除原因。协调器对当前有效源的无效状态发经过鉴权、绑定当前提交序号的 ABORT；超时由各节点独立熄灭。 |

应用信封还包含 version、type、协调器 epoch、目标 node boot nonce、组 membership、apply_at、payload digest、续租序号及截止时间；ACK 带键、状态及实测回报。版本、组成员、顺序与公共字段用规范编码计算同一个组 digest，module_id 按目标校验并纳入签名/信道身份。随机 boot nonce 和 epoch 断开旧会话；协调器重启先停止续租并等待旧 lease 安全排空。禁止不同 epoch 复用旧排程或从 NVS 恢复可见读数。

## 调度与故障行为

1. 初始交换多次四时间戳探测。在协调器单调参考时钟中，根据往返、收发队列不确定度及振荡器漂移估算偏差区间。采用最低 RTT 样本和带龄期上界的区间，不把 Wi-Fi 对称性当保证。连续验证，若估计半宽超过 5 ms、参考时钟跳跃或无可信样本则消隐，当前已排任务不能随系统墙钟跳跃。实际使用本地单调定时器，发起时根据 OLED 隐藏写入耗时，建议预留 300 ms。
2. PREPARE 绑定同一摘要和未来 apply_at。接收时至少提前 100 ms、最多 2 s。节点先关数字，确认旧 OLED 已隐藏，然后在黑屏写待显示标签、单位和小数提示，锁存 32 位并继续关闭 /OE。全部 READY 到齐才发送 COMMIT。视觉上允许中间空白，两类显示不混搭新旧帧。
3. COMMIT 只接受当前暂存且尚未到切换时间的帧，返回 ARMED。到期时 OLED 显示新语义，等待经光学验证的可见延迟，再允许匹配的数字。显示成功才报 APPLIED。取消或错误时先关数字再清 OLED；I²C 无响应则硬件断 OLED 电源。空白前后的控制、上升/下降时间由独立驱动验证。每板永远由本地健康和硬件许可决定最终使能。
4. 协调器遇超时、任一失败或掉组，立即重发 ABORT，并停止续租。每次 COMMIT 给最长 1 s 初始租约。周期约 250 ms 收集全部同序号 APPLIED/在线健康证明，全部到齐才发受同一截止约束的 RENEW。收齐本轮 ACK 才开启下一轮。任何续租时间不得超过发送时参考时间 +1 s，且在数据 TTL 之内。未感知断连的节点依赖本地 lease 关屏；本地已知断连、OLED 故障、时钟失锁、应用停止、OTA 和重启立即请求关屏。OTA 后以签名的有效镜像、回滚自检、新会话及全新的同步/事务重新进入。故障锁存只能经硬件规定的本地复位/再 ARM，协议无相关命令。
5. ACK 丢失可重发相同请求，按事务键幂等。若任何节点漏收 COMMIT 或 ABORT，部分节点可能短暂显示该帧。新事务只有在全部 READY 后启动，此时所有组员已结束旧帧。未获新租约时，没有协调器或断网的组最多在最后一次有效租约截止外加时钟与调度误差后熄灭。禁止对剩余节点显示有效的缺位组合数据。

## 光学、网络和低压验收

暂定同一成功组的管侧光学起亮最大偏差 p99≤30 ms，已接受试验窗口最大≤50 ms。初步预算包括两端时钟差≤10 ms、调度差≤10 ms、面板与管侧路径差≤30 ms，分别上仪器核实。健康窗口内完整组正式验收另记录成功率、准备等待时长和光学空窗，缺席或超过截止的节点计失败，不能剔除异常样本。测每块 /OE、RCLK、OLED 同步标记、上屏光敏信号和代理 LED，用一台示波器/逻辑分析仪的同一时基。每个射频档位记录至少 1000 帧，含弱信号、竞争、网络重连和故障注入，计算 max−min、p50/p95/p99/max、缺片率和失联到熄灯。验证任意同板数字可见时对应标签已可读、对应帧 ID 相同；局部死机到硬件消隐另量。Wi-Fi 的包交付和时钟误差决定实现边界，组合显示不能保证严格同时或严格全有全无。

软件入口为 `python -B -m unittest -v`。主机仿真用合成时钟、内存传递、OLED 假件和无 GPIO 的位图，覆盖 3/6/9 位、事务和故障。真实 TLS/序列化、协调器持久运行、ESP-IDF 定时、SSD1305/1306 实际 OLED、签名启动/OTA 及硬件引脚均需要独立低压原型验证。 [状态机](low_voltage_display.py) · [测试](test_low_voltage_display.py)
